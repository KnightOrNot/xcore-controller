| 项目 | 实际内容 |
| --- | --- |
| 帧数 | 99；timestamp 为 0～9.8，间隔约 0.1 s，即约 10 Hz |
| `state` | float32[20]，可分成两组 10 维 |
| `actions` | float32[21]，前 20 维可分成两组 10 维；额外一维语义未知 |
| 额外 action | 第 0～88 帧为 −1，第 89～98 帧为 +1；不能直接当作夹爪、力或终止标志 |
| 图像 | `image`、`left_wrist_image`、`right_wrist_image` 三路，首帧均为内嵌 224×224 RGB PNG |
| 字符串 | `adv_ind`，本段均为 `positive`，不能据此当作任务指令 |
| 任务索引 | `task_index=0`；单个文件未给出完整自然语言任务描述 |

用户随后已确认该样例来自双臂；左右两臂的排列顺序仍需字段说明确认。

每组 10 维的前三维数值符合位置的量级；中间六维可分成两个单位正交向量，
全部样本的单位范数／点积误差小于约 4×10⁻⁸，符合旋转 6D 表示。
但文件没有逐维名称：不能仅凭这些数值证明向量代表旋转矩阵的列还是行，
也不能证明坐标系、位置单位或 TCP 定义。
两组第十维在 state 和 actions 中均为 0，无法据此判断是“开度”还是“闭合度”。
不能仅凭本样例认定 actions 等于下一帧 state。

## 单台 CR7 的建议数据契约

```text
pose10 = [x, y, z, R00, R10, R20, R01, R11, R21, g]
```

位置为米，R 为同一基座坐标系中工具 TCP 的旋转矩阵，按第一列、第二列拼接。
实现应显式使用 `concatenate([R[:, 0], R[:, 1]])`；不要直接对 `R[:, :2]`
做默认行序 flatten。10 是表示维数：机械臂位姿仍是 6 个独立自由度，旋转 6D 有约束。
为兼容现有 raw 闭合度，建议 `g=0` 为全开、`g=1` 为全闭，并在 manifest 写清楚。
若训练端要求反向定义，只在导出时显式转换，不改变原始反馈含义。

| 字段（样例兼容命名） | 建议内容 |
| --- | --- |
| `state` | float32[10]，实际从臂 TCP 位姿＋实际夹爪闭合度 |
| `actions` | float32[10]，明确时间语义的目标 TCP 位姿＋目标夹爪闭合度 |
| `image_cam1`、`image_cam2` | 两组 RGBD，每组包含 RGB 和原始 depth，分别记录帧号和时间戳 |
| `wrench` | 预留 float32[12]：两路各为 Fx/Fy/Fz（N）及 Tx/Ty/Tz（N·m），按第一路六维、第二路六维拼接 |
| `wrench_valid` | bool[2]，每路独立；无传感器时必须 false，不能把占位 0 当作实测 |
| `instruction` | 任务描述字符串；episode 固定内容可存一次并通过索引关联 |
| 时间及有效性 | state/action/每台相机的 color 与 depth/两路力的独立时间戳、时钟域、frame index、匹配误差和缺失标记 |

原始深度按无损 uint16/Z16 保存（例如 16 位 PNG），同时保存 depth scale、
color/depth 内参和二者外参，明确深度到米的换算。伪彩 JPEG、8 位图和普通有损视频
不能替代原始深度。保留原生深度；如另生成对齐 RGB 的深度，记录对齐方式、目标坐标系
和无效像素，不能默认原生 RGB 与深度同像素对应。

两路力分别记录传感器标识、参考坐标系和单位，具体设备与安装位置尚未确认，
不能将两路自行解释为左右臂，也不能将控制器估计量当作外部力传感器实测。

如果要输出标准 LeRobot 数据，导出层将 state/actions 映射为
`observation.state`/`action` 并生成对应 features、任务元数据及图像／视频索引。
如果训练代码直接消费样例列名，则输出其所需的 Parquet schema，不能仅改文件扩展名。
双臂场景才将两个 pose10 拼为 20 维；当前单 CR7 不伪造第二臂或不明的第 21 维。

actions 推荐表示在观测 t 之后请求执行的绝对目标，不是把实际 state 整体后移一帧。
需要明确使用请求目标、限位后接受的目标还是实时插值输出；建议保留三者的来源说明，
训练特征选择其一，不混用。若需要未来实际状态，应另设 future_state 与时间间隔、有效标记。

## 现有缺口和实施顺序

1. **采集和运动学**：现有 raw 保存六轴实际关节＋夹爪以及请求目标，共七维；
   `gello_follower.get_observations()` 的 `ee_pos_quat` 仍是全零占位。
   应在当前唯一 SDK 会话内获取真实末端状态，或对同一帧关节反馈执行经过验证的正运动学。
   目标关节也使用相同 CR7 模型及 TCP 计算 FK，得到目标 pose10。
   核实实际机型、模型标定、基座／参考系、法兰到夹爪 TCP 变换；不能照搬其他 CR 型号模型。
   原始关节、原始位姿、目标、时间戳和模型版本仍保留，便于重算与排查。
2. **相机记录**：当前 HTTP/MJPEG 是有损、允许跳帧的预览，不是记录管线。
   在远端已有 pipeline 旁增加独立队列／写盘线程保存帧和元数据，避免重复打开相机；
   如要求无损 RGB，应保存编码前 RGB／PNG，而不是把 JPEG 解码后改存 PNG。
   两台相机都保存 color 和原始 depth，深度使用独立无损通道；记录每台 RGBD 配对、
   两台相机之间的匹配误差与缺帧标记，不能仅保存彩色流。
   对齐本地机械臂与远端相机的时钟，保留估计偏移、时钟域、逐流时间戳和有效标记；
   不把 SSH 网络到达时间当作曝光时间，也不把不同主机 monotonic 值直接比较。
3. **独立远端数据项目**：规划 `xcore-adapters` 负责数据语义、FK 和特征映射，
   `xcore-dataset` 在远端协调 raw 接收／封存、同步、LeRobot 转换和 LeLab 浏览管理；
   controller 只增加薄脚本入口并按需通过 submodule 引用。LeLab 不是转换引擎，
   转换使用 LeRobot API；不修改或 monkey-patch 共享 lerobot-converter 和上游库。
   先保留不可变 raw，再后台转换、校验并发布不可变数据集版本，之后本地按需通过有线
   SSH／rsync 拉取完整成品并校验，不再将本地单文件导出脚本作为主方案。
4. **版本与验收**：新 raw/schema 另设版本，保留现有七维数据链兼容。
   校验旋转正交性、夹爪范围、目标来源、RGBD 配对、深度 dtype／scale／标定、
   跨流帧龄、掉帧、episode 边界和缺传感器掩码。
   明确训练端是否要求样例的第三路图像、21 维 action 和附加奖励字段，不能自行补值伪造。

已有七维记录在具备匹配模型／TCP 配置时可以离线计算末端表示；未采集的图像和力数据
无法通过转换器补回来。实现重点先在采集层，随后才是导出格式。
